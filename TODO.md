- [x] **Restricted research pools with agent registration, replacing quarantine.** *Done 2026-10-27 ([proposal](docs/proposal-research-pools.md)).* The agents keep their own "do not publish" list instead of using quarantine. The user's finding (2026-10-25): an agent that hits a safety stop on a record cannot complete that record, but is allowed to use its research once it is completed, probably because the stops are often false positives. Quarantine fits neither half: it counts the record complete without research, and seals it. **Decided: pools replace quarantine.** Likely design, to go through the workflow:
  - **Entering a pool.** An agent that hits a safety stop puts the record in a pool with the reason (the role quarantine's `cyber-stop` origin played), so it leaves the open work of agents that cannot finish it; the human can add records too.
  - **Working it.** A pool's records are open only to agents registered to it: they take them as a shared workpool (claims, status, review queue). Other agents never see them as available work and are refused when they write to them.
  - **Registration.** Agents register under a name, and an agent without a registration can register itself; registered agents join a pool's list to work it. The app only provides the capability: the human directs which agents join which pool, so there is no approval step.
  - **After completion.** A completed record becomes available: every agent may read it and build on it as a prerequisite. It still stays in the pool as do-not-publish for agents not registered to it, so no agent that cannot work it writes to it and triggers the safety stop again.
  - **Unlike quarantine**, a pooled record is not complete until it is researched, so meters and parent completion count it as open work.
  - **Quarantine moves into pools:** existing quarantine records migrate to pools, and quarantine's commands and seal go.
  - **To decide in design:** how pooled records show in meters, `status`, the GUI and history; and the migration of `quarantine.json` and the `--directed-by` seal.
