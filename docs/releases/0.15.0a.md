# Scopework 0.15.0a

**Comparison range:** `v0.14.0a..v0.15.0a` (the tag is placed on the package commit). A minor release under the version rules in [docs/building.md](../building.md): it adds features (data items, the project store and its promotion, artifacts and address spaces, research pools, proofs, the shared work queue), so 0.14.0a becomes 0.15.0a.

**Upgrading.** This package is Build 000007, MSI version 0.15.7. It upgrades 0.8.0 and every 0.13.x and 0.14.x package in place; the UpgradeCode, executable names and research home are unchanged. Nothing changes on upgrade: a project's catalog moves to a newer format only when it uses something new, and earlier versions then refuse it (format 6 with its first data item, 7 with an artifact or address space, 8 when promoted). A project's store is optional (`research store init`), and promotion is the owner's one-way decision. Projects with quarantine records from 0.14 refuse writes until `research pool migrate-quarantine` moves them into a pool.

## What changed

The full list is in the [changelog](../../CHANGELOG.md#0150a---2026-10-29); this is a summary by area.

### New

- **Data items** ([proposal](../proposal-storage-backend.md)). Globals, tables, strings and vtables are records beside the functions in a chunk, with an address and a length, researched like functions and connected to them by prerequisites in either direction.
- **The project store** ([design](../design-storage-backend.md)). `research store init` builds a project's whole history from its receipts into a compressed store beside the files, which stay authoritative; `store history`, `show` and `catalog` answer for any revision; the coordinator keeps it current. It also follows the project tools' annotation ledger row by row and lists where the ledger and the catalog disagree (`store conflicts`, `store annotations`). `store compact` keeps it small: 38 MB for `3-3-5a`'s 37,910 commits, against 277 MB of receipts.
- **Artifacts and address spaces** ([design](../design-storage-promotion.md)). A project names its input files and adds address spaces besides the default one (a file's offsets, another image, another processor), so data-only projects have somewhere to put their research.
- **Promotion** ([design](../design-storage-promotion.md)). `research store promote`, the owner's step, makes the store authoritative: commits write it, receipts stop, and acceptance moves to the research body and evidence, so renames, moves and identity amendments no longer touch completion. `research annotate` changes annotation rows of a promoted project.
- **Research pools replace quarantine** ([proposal](../proposal-research-pools.md)). Only a pool's registered members change its records; everyone else may read and build on them.
- **Proofs** ([proposal](../proposal-proof-records.md)): a function can name its recreation and the tests that check it, and a project can require one to complete a function.
- **Shared work queue** ([proposal](../proposal-shared-work-queue.md)): `job run --shared` leases a resource of the whole research home, such as a verification worktree.
- **`deps set` conflicts only on the function's own prerequisites** ([proposal](../proposal-deps-record-token.md)), and **commands run as their caller** through the coordinator ([proposal](../proposal-caller-identity.md)).

### Fixed

From the reviews of each batch ([review fixes 4](../proposal-review-fixes-4.md), [5](../proposal-review-fixes-5.md)), the app-wide reviews of 2026-10-27 ([quality 1](../proposal-quality-review-1.md), [2](../proposal-quality-review-2.md), [3](../proposal-quality-review-3.md), [bugs 1](../proposal-bug-review-1.md), [2](../proposal-bug-review-2.md)) and of 2026-10-29 ([quality 4](../proposal-quality-review-4.md), [bugs 3](../proposal-bug-review-3.md)). The most important:
- The store never deletes a segment log that still holds entries; damage is refused (`store_damaged`), not repaired away.
- A prerequisite in another address space is written `S<n>:0x…`, so saving a record's prerequisites back cannot change them.
- A coordinator whose home was deleted exits even with stuck work, and no longer recreates the home.
- Pool access is checked on every write path, and only members take records out of a pool.

### Performance

- A store sync after a few commits looks up only the receipts it steps over (one commit on `3-3-5a`: 12.8 s to 1 s), and a promoted commit reads only the store's active segment.

## Validation

- **Tests:** `cargo test --all-targets` passes on Windows (250 tests). Every fix from the reviews has a regression test.
- **Lint:** `cargo clippy --all-targets -- -D warnings` reports nothing and `cargo fmt --check` is clean.
- **On copies of `3-3-5a`** (read only from the live home): store init, verify and compaction over 37,910 commits; a promotion rehearsal converted 5,466 acceptances with every one of 31,514 records keeping its effective status; commits after promotion take as long as a read. Details are in [the proposal](../proposal-storage-promotion.md#validation-2026-10-28).
- **Packaging:** `installer/build.ps1` reserved Build 000007 and packaged `Scopework-0.15.0a-x64.msi`. The executable reports `Scopework 0.15.0a (Build 000007)`; the local MSI's SHA-256 is `7d3025dd492bb90eee502687a56e93a54db4bb7c3f4a52dcfd7a65283b423b44`. The release workflow rebuilds the MSI from the tag with the same build number.
- **Not done:** installing over 0.14.0a, and promoting a live project (the owner's decision).

## Known limitations

- **Promotion and the project tools.** The tools' staleness checks hash whole report files; after promotion pins are body hashes, so the tools must move to `research annotate stale` before a project they work on is promoted.
- **Timing-sensitive tests.** Three tests assume a child process starts within a few hundred milliseconds and fail now and then under heavy disk load; they pass alone (recorded in `TODO.md`).
- **Readers still load `project.json`.** The store saves history space and commit-time scans, but every reader still parses the whole catalog; moving readers onto the store is a later stage.
- **Tab overflow** and **effective-status recursion**, as in 0.14.0a.
