# Proposal: multi-agent friction, code quality and secondary panels

Work brief of 2026-10-18 (TODO.md items A, B and C). This document records the research, design and accepted approach before implementation, and the acceptance criteria each part is checked against.

## Research

### Code quality (B): findings

1. Link rewriting changes text it does not need to (above). `node delete` has the same defect.
2. `node delete` reopens completed records but does not put them in the review queue, and leaves claims and review-queue entries for deleted nodes.
3. The annotation ledger is reformatted and stored twice per move (above).
4. File replacement is not robust to Windows sharing violations (above).
5. Completing a report computes effective status for the whole project twice. `Library::effective` evaluates every node to answer for one.
6. `same()` converts two whole catalogs to JSON values on every commit, after `read_pending` has already compared fingerprints.
7. `history show` parses whole receipts, including multi-megabyte sidecar texts, to summarise them.
8. `research wait` parses the 10 MB catalog four times a second, and with `--complete` evaluates the whole project each time.
9. GUI writes do not wait for the project lock.

No data-loss defect was found in journaling, recovery, tokens, imports or deletion archiving. The existing tests pass, and `cargo fmt`/`clippy -D warnings` are clean.

## Design and accepted approach

### A. Multi-agent friction

**A1. Path rewriting touches only references to moved files.** A reference changes only if the path it resolves to lies under a moved folder, or if the report holding it moved and the resolved path exists in the project. All other text, including quoted source strings, keeps its exact bytes, so unrelated completed records are no longer reopened. Applies to moves, deletions and link repair.

**A2. Moves read only the reports that can change.** A persisted reference index (`tools/workspaces/scopework-cache/report-references.json`) records the canonical folder names (6-digit node IDs, 8-hex RVAs) each report mentions, keyed by size and modification time under the same racy-timestamp rule as the report hash cache. A move reads the moved reports plus the reports that mention a moved folder; the rest are only statted, in parallel. `repair_legacy_links` still reads everything.

**A3. Ledger paths are repathed in place, idempotently.** The journal records a ledger remap (old → new report folders) instead of two ledger copies. On commit, Scopework applies it to whatever the ledger contains at that moment, replacing only the `"report"` string values in the existing text. Formatting, key order and line endings are preserved. The same pass repairs any canonical-shaped `"report"` path that names an existing node at an outdated location, so a row reverted by a concurrent tool write is repaired by the next move. A tool's concurrent write can no longer leave an unrecoverable journal. Pending journals in the old full-text form are still recovered as before.

New `research node resolve PROJECT PATH...` maps any canonical-shaped report or data path (old or current) to the node and its current path. `node batch` results list each moved report's old and new path and the number of ledger rows repathed.

**A4. Reads continue while recovery is blocked.** If a pending journal cannot be resumed, read-only commands answer from the committed catalog and print a `recovery_blocked` warning on stderr. Writes fail with a message naming the conflicting file, the pending journal and the supported recovery. The GUI shows the message and keeps its last snapshot.

**A5. Robust file replacement on Windows.** `atomic()` retries the rename for up to about 3 s on sharing, lock and access violations. `research wait` checks the catalog's modification time before parsing it.

**A6. Fair lock queue.** Waiters register in `.project-locks/<id>.waiters/` with a nanosecond ticket and hold a lock on their own record, so dead waiters are detected and removed. A writer goes when it is the oldest live waiter. A reader goes when no older live writer is waiting, so readers share a turn and cannot starve writers. Immediate acquisitions respect the queue too. `research locks` lists the queue in order. Processes from older versions do not take part, but stay correct.

**A7. Record-level preconditions for catalog batches.** Batch schema 2 drops the global `expect_revision` and requires `expect_node_revision` on every `update`. Unrelated commits no longer conflict, while moving, renaming or reclassifying a record still requires its current revision. Reorders still list every child, and creations still check their parents. Schema 1 is unchanged.

**A8. Shorter lock holds.** The GUI holds its shared lock only while reading catalog and sidecar files, then builds meters unlocked. `research wait --complete` re-evaluates only after the catalog changes, and at most every 2 s. Commits compare catalogs as typed values.

**A9. GUI writes wait** up to 60 s for the project lock, in their background thread. The refresh still answers immediately and keeps its snapshot.

**A10. Reclaiming duplicated ledger history (opt-in).** `research journal PROJECT` reports bytes held in sidecar texts over 1 MB in completed receipts. `--compact-sidecars` replaces each such pair with a JSON change list (the changed values with their JSON paths) plus SHA-256 of both texts. This is irreversible for the exact historical bytes and is never automatic. Pending journals are never touched.

### B. Code quality

Fix findings 1–9 as above (B1, B3, B4 and B8 are covered by A1–A9). B2: deletions queue the completed records they reopen and drop claims and queue entries of deleted nodes, all in the same transaction. B5: completion evaluates the closure it needs once. B6: typed comparison. B7: history summaries skip sidecar text.

### C. Secondary panels

One shared classic style module (`classic.rs`) holds the palette, bevels, group boxes and the widgets: raised bevelled buttons, sunken fields and list boxes, square check boxes, a tab strip, menu items with navy highlight, and a window with navy title bar, bevelled close button and raised border. The dashboard uses the same painters. Its approved layout and appearance do not change.

Research records becomes a classic window titled for the dashboard's selected project:

- **Left:** a "Records" group box with the find field, three filter check boxes and the record tree in a sunken list.
- **Right:** a header (kind, name, RVA, effective status, flag and review-queue notices) and three tabs:
  - **Report:** the editors, plus **Save**, **Mark complete…** and **Discard changes**. Mark complete is enabled only when completion is possible, and otherwise says what blocks it. It asks for confirmation, with the scope criteria, before attesting. This replaces the checkbox that changed what Save did.
  - **Organize:** add a child, prerequisites, context-only membership, review flag and the data folder.
  - **Project:** research scope, binary identity, tool folders and inventory import.
- **Status bar:** messages, progress and unsaved-edit state.

The project follows the dashboard tab, so the duplicate project buttons go. **File > New project…** opens a small dialog, which the empty state also offers. About becomes a classic dialog with an OK button. Agent and CLI workflows do not change.

## Acceptance criteria

- A move or delete leaves byte-identical every report that does not reference a moved or removed folder. `.\x.cpp`, `..\src\x.cpp` and other relative literals survive in moved and unmoved reports. A moved report's relative links to unmoved project reports are still rebased.
- A move in a fixture reads only moved and referencing reports. Verified by counting reads in a test: the persisted index is consulted and unrelated reports are not opened.
- After a move, the ledger keeps its original line endings and formatting except for the repathed values. A ledger changed by another writer between planning and commit still commits with the remap applied. A row reverted to an old path is repaired by the next move. The journal no longer contains ledger text.
- `node resolve` returns the current path for old and current paths.
- A blocked pending journal does not prevent `node show`/`status`, which warn. Writes report the file and journal.
- Waiters are served oldest first. A waiting writer is not overtaken by new readers. A killed waiter's record is ignored and cleaned up.
- A schema-2 batch succeeds after an unrelated commit and fails when the moved record's revision changed.
- Deletion queues reopened completed records and drops sidecar entries of deleted nodes.
- `--compact-sidecars` reclaims sidecar copies in completed receipts only, and reports what it replaced.
- The GUI shows classic chrome, buttons, fields, tabs and group boxes in light and dark modes. The dashboard's main view is unchanged. Completion works from the confirmation dialog.
- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and `cargo test --all-targets` pass with no warnings. New behaviour has focused regression tests on small self-cleaning fixtures.
